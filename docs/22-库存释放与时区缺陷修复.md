# 22 · 库存释放与时区缺陷修复

> 日期：2026-08-12　基线：`959da57`
> 触发：修复 `docs/20` §1.1「未支付订单不释放库存」。过程中集成测试打真库，暴露出一个影响更大的既有时区缺陷。

## 1. 修复了什么

### 1.1 余量生命周期补全

**问题**：下单扣减余量（`DecrProductStock`），但没有任何路径归还。`IncrProductStock` 已定义却**零调用方**。

后果：下单不付款、退款、租期结束，余量都只减不增，商品一路扣到 `sold_out` 且无法恢复。

**依据**（`docs/03-功能需求-算力撮合交易.md`，语义由需求定死，非自行设计）：

| 需求 | 内容 |
|---|---|
| REQ-A-012 (P0) | 余量实时更新：成交/**释放**自动增减可售量；售罄自动下架 |
| REQ-A-023 (P0) | 库存锁定：下单锁定余量，超时（15 分钟）未支付**自动释放** |
| REQ-A-043 (P0) | 到期处理：到期自动置「已完成」并**释放余量** |

> **REQ-A-043 此前完全未实现**，`docs/20` 初版也遗漏了它——原记录只写了「未支付」和「退款」两条。余量是**并发容量**而非一次性库存，租期结束必须归还。

**改动**：

| 位置 | 内容 |
|---|---|
| `repository.go` `TransitionOrderStatusTx` | 新增。守卫式状态流转，仅当订单处于允许的来源状态时才流转，返回是否真的发生 |
| `repository.go` `ListExpiredUnpaidOrderNos` / `ListExpiredLeaseOrderNos` | 新增。扫描到期订单；后者以 `lease_end_at IS NOT NULL` 排除买断订单 |
| `service.go` `releaseStock` | 新增。守卫流转 + 归还余量，**同一事务内完成** |
| `service.go` `CloseExpiredUnpaidOrders` | 新增。REQ-A-023 关单任务 |
| `service.go` `CompleteExpiredLeases` | 新增。REQ-A-043 到期任务，并同步吊销访问凭证 |
| `service.go` `CancelOrder` / `CompleteRefund` / `CompleteOrder` / `AdminUpdateOrderStatus` | 改为经 `releaseStock`，不再绕过归还 |
| `main.go` | 定时任务接线，5 分钟粒度，**启动即跑一次** |

**幂等性与并发安全**：归还必须与状态流转在同一条条件 `UPDATE` 的判定下完成。若用「先查状态再改」，关单任务、买家退款、运营改单三条路径并发命中同一订单时会各自归还一次，余量凭空变多。条件 UPDATE 由 InnoDB 行锁串行化，只有一个事务能拿到 `RowsAffected=1`。已有并发测试覆盖（8 goroutine 抢同一笔，实测仅 1 次归还）。

### 1.2 顺带修掉的商品状态缺陷

原 `IncrProductStock` 无条件执行 `SET status='active'`。这意味着**被运营强制下架（T-048）或风控冻结的商品，会因为一笔退款而自动重新上架**。

已改为仅 `sold_out → active`，与 `SetProductStockTx` 的既有写法保持一致。

### 1.3 数据库时区偏移（本次最严重的发现）

**这不是新引入的问题，是既有缺陷**，只是此前没有定时任务去读这些时间戳，所以从未暴露。

生产 DSN 缺少 `loc` 参数：

```
root:password@tcp(127.0.0.1:3306)/tokenfactory?parseTime=true&charset=utf8mb4
```

`go-sql-driver` 默认以 **UTC** 序列化 `time.Time`，而本项目 MySQL 会话时区是 **+08:00**。实测：

```
Go 侧 now+10min : 2026-08-12 16:50:37
DB 中实际存储   : 2026-08-12T08:50:38Z     ← 差 8 小时
DB NOW()       : 2026-08-12T16:40:37Z
被判定为已过期   : 1  (期望 0)
```

**若不修就上线本次的定时任务，后果是灾难性的**：

- 每笔订单创建后 5 分钟内即被关单任务判定超时并取消
- C-06 访问凭证一签发就被吊销
- `lease_end_at` 立即被判定到期

**修复**（双保险，不依赖配置文件写对）：

1. `config.yaml` 补 `loc=Asia%2FShanghai`
2. `pkg/db/mysql.go`：
   - `normalizeDSN` 自动补齐 `parseTime=true` 与 `loc`，并打 WARN 日志
   - `verifyTimezone` **启动时实测一次时间往返**，偏差超 1 分钟直接拒绝启动并说明原因

实测三种情况均符合预期：

| 场景 | 行为 |
|---|---|
| 正确 DSN | 连接成功 |
| 缺 `loc` | 自动补齐 + WARN，连接成功 |
| `loc=UTC`（与库不一致） | **拒绝启动**，报「相差 -7h59m59s ...」 |

## 2. 验证

### 2.1 常规

`go build` / `go vet` / `go test ./...` 全绿。

### 2.2 集成测试（真实 MySQL）

新增 `internal/compute/stock_release_test.go`，**10 个用例全部通过**。

默认跳过，需真库时：

```bash
TEST_MYSQL_DSN='root:PW@tcp(127.0.0.1:3306)/' go test ./internal/compute/ -run TestStock -v
```

测试自建独立库 `tokenfactory_stock_test`，结束即删，不触碰业务库。

| 用例 | 验证点 |
|---|---|
| `CloseExpiredUnpaidOrders` | 超时未支付 → 关单并归还 |
| `UnexpiredOrderNotClosed` | 未到期不得被关闭（**正是这条最初失败，暴露了时区缺陷**） |
| `ReleaseIsIdempotent` | 重复执行只归还一次 |
| `ConcurrentReleaseOnlyOnce` | 8 goroutine 并发，仅 1 次归还 |
| `RefundRestoresStock` | 退款归还 |
| `CompleteExpiredLeases` | 租期到期 → 完成并归还 |
| `PerpetualLeaseNeverExpires` | 买断订单永不被关 |
| `SoldOutRecoversToActive` | 售罄归还后恢复在售 |
| `OfflineProductNotResurrected` | 下架/冻结商品不被自动上架 |
| `TerminalStatusNotReleased` | 终态订单不再归还 |

新增 `pkg/db/mysql_test.go`：DSN 修正逻辑 8 个子用例，含凭据含特殊字符、异常 DSN 透传等边界。

> 若这次只做纯函数测试，时区缺陷会一路带到生产，并在定时任务启用当天集中爆发。

## 3. 部署注意

1. **必须使用带 `loc=Asia%2FShanghai` 的 DSN**；即使漏了，`pkg/db` 也会自动补齐并在时区错配时拒绝启动
2. 若已有历史数据是在错误时区下写入的，其 `payment_expires_at` / `lease_end_at` 存在 8 小时偏移，**上线前需要修数**。当前库中无业务数据，暂不涉及
3. 定时任务为 5 分钟粒度，支付超时 15 分钟，故最迟超时后 5 分钟释放余量
