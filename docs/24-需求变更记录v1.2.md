# 24 · 需求变更记录 v1.2（零租托管交付与灵活租赁）

> 版本：v1.2-draft ｜ 日期：2026-10-28 ｜ 状态：待审查
> 来源：业务负责人 2026-10-28 提出的撮合平台优化需求（零租可用性、灵活计费、分卡、模型一键部署）
> 影响范围：算力撮合模块（docs/03）、支付结算（docs/04）、多端工作台（docs/06）、运营后台（docs/08）、风控（docs/09）、架构（docs/16）、API（docs/17、`docs/api/`）、协议正文

---

## 1. 背景

零租商品上架时不采集登录信息、不探活；买家付款后要等供给方手工回填凭证，平台无法验证凭证真实可用；到期"吊销"只作废了平台生成的 key/value，买家手里的真实 SSH 密码照样能登录（Issue #8）。结果是：**商品可售不代表可用，到期不续费也停不下来**。

同时市场上灵活机器增多，现有单一计费方式、整机库存池无法支撑按时/日/周/月/包夜和按卡数拆分出租；买家还希望租到卡后能直接把模型跑起来。

## 3. 关键决策

| # | 决策 | 理由 | 推翻 / 影响的既有口径 |
|---|------|------|--------------------|
| D-1 | **建立算力调度系统**，由平台承担托管零租的技术履约（接入、探活、卡槽分配、开通、访问控制、回收）——业务负责人 2026-10-28 确认 | 不掌握开通与回收，就无法保证"付款可用、到期即停"，C-09 无法成立 | 推翻 Q-01 暂定口径「供给方手动开通+回填凭证」及其衍生：REQ-A-041「v1 不做底层自动编排」、docs/01 §1.3 Out of Scope「不做实际算力编排」（该处误引 Q-09，实为 Q-01）、docs/02 第三层「v1 不做底层调度」、需求方案 v1.0「不自建算力调度系统」、前端仓库 CLAUDE.md「第一版不做：算力调度系统」，上述文档随 T-104 改写；托管范围之外（人工模式、算力中心、整柜）仍按 Q-01 原口径；法律红线（算力理财/份额/虚拟货币）不变 |
| D-2 | 人工（`manual`）与托管（`managed`）两种履约模式并存，存量商品一律 `manual` | 存量商品、算力中心、整柜等无法托管的形态继续可售；零迁移风险 | C-06 人工流程保留不变 |
| D-3 | 访问网关独立部署在单独主机，用 sshpiper（MIT）+ 自写路由插件 | 买家流量不经业务主服务；网关不存业务数据，被攻破也拿不到订单与资金数据；遵循"不自研框架" | docs/16 新增一个部署单元 `cmd/accessgw`（仍在单体仓库内） |
| D-4 | 节点管理**不装常驻 agent**，平台经 SSH 管理通道执行命令 | 供给方接入门槛低；不在供给方机器上留平台常驻进程；升级只升平台侧 | — |
| D-5 | 托管 v1.2 仅支持 NVIDIA | 探活、隔离、健康检测依赖 `nvidia-smi` / nvidia-container-toolkit | 国产卡继续走人工模式（Q-39） |
| D-6 | 托管模式**付费成功即生效**：无签收、无需供给方操作，自检通过即可登录；开通耗时不计入租期 | 业务负责人 2026-10-28 确认（Q-41） | 人工模式签收流程不变 |
| D-7 | 一键部署只部署平台目录内、经真机验证的模型，只用 vLLM，只对租约私有可达 | 判定结果可复现、可解释；不对公网暴露减少滥用与合规面 | 公网端点后置（Q-43） |
| D-8 | 一键部署与 Token 工厂分离 | 一键部署是买家自用的私有服务，平台不转售、不计 Token 费；Token 工厂（docs/05）对外售卖口径与备案要求不同 | docs/05 不变 |
| D-9 | 节点 **60s 轻量探活 + 12h 完整探活**；租期内机器原因停机自动记录，**补偿买家时长或费用，由供给方承担**（docs/25 §25.7.6） | 业务负责人 2026-10-28 确认（Q-37） | 补偿不再依赖 Issue #12 人工处理 |
| D-10 | 托管订单**租期结束后一次分账**（停机补偿结算完成后），宽限期不收保管费 | 资金留在易宝待分账账户，补偿可直接从中退回买家、扣减供给方应结，无需向供给方追款；业务负责人确认"一次性结清"（Q-33） | 改变 `payment.splitEligible` 对托管订单的分账时点；人工订单不变 |
| D-11 | 第三方组件必需的 gRPC 可以接受 | 业务负责人 2026-10-28 确认 | docs/16 §9 已加例外说明 |

## 8. 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 整机托管 root 持久化 | 买家有 root，可留后门，平台无法保证回收 | 到期进入 `needs_reimage`，供给方确认重装并探活通过才可再售；上架规范与使用规范明示 |
| 容器逃逸 | 容器内 root + GPU 驱动面 | 禁止 `--privileged`、docker.sock、宿主网络/PID/IPC；基础镜像按 digest 固定；驱动版本下限 |
| 供给方物理接触数据 | 供给方拥有宿主机，能读取容器数据 | 无法技术消除；协议告知，买家敏感数据自行加密 |
| 网关带宽成本与单点 | 买家全部 SSH/数据传输流量经网关 | 北京独立主机按流量计费；网关无状态可水平扩展；主服务不可达时拒绝新连接（安全优先） |
| 易宝待分账能力 | D-10 依赖三项易宝能力：① 待分账资金留存期限（月租订单可能超限）；② 同一笔支付多次部分退款；③ 待分账状态下部分退款且剩余金额仍可分账 | 上线前向易宝书面确认；②③ 未确认前停机补偿只开放"顺延"；① 超限时按上限分段结算 |
| 供给方回款推迟 | D-10 下托管订单租期结束才分账，月租供给方约 1 个月后回款 | 上架页与上架规范明示；Q-46 待业务负责人确认 |
| 内部接口暴露 | 网关调主服务的 `/api/v1/internal/*` 若经公网可达，HMAC 是唯一防线 | 仅内网 nginx server 块监听；公网块与前端 Caddyfile 对该前缀返回 404；firewalld 只放网关内网 IP |
| P12 局限 | "主服务器 IP 不可达租约端口"只证明对单一外部来源关闭，不等于对全网关闭 | 周期复测 + DOCKER-USER 规则由平台下发；上架规范要求端口仅对网关开放 |
| 显存估算偏差 | 可行性判定依赖目录参数 | 目录条目上线前必须有真机验证记录；开销取实测值 |
