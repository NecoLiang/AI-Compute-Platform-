> 版本：v1.0 ｜ 日期：2026-07-13 ｜ 状态：待审查 ｜ 产出：ARCH
> 技术栈：Go + MySQL + Redis。原则：**稳定优先、够用就好、不过度设计**。

## 1. 总体架构

### 1.1 架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 架构风格 | **单体应用 + 包隔离** | 并发量不高（日均 <1000 订单），单体足够；按 package 隔离模块，未来可拆 |
| HTTP 框架 | **gin** | 性能好、生态成熟、中文社区活跃 |
| 数据库 | **MySQL 8.0** | 交易类数据强一致性需求 |
| ORM | **sqlx + 手写 SQL** | 避免 GORM 隐式行为，显式控制查询；简单 CRUD 可用 GORM |
| 缓存 | **Redis 7** | 会话/session、验证码、余量锁、轻量队列 |
| 鉴权 | **JWT (access+refresh)** | 无状态、可扩展 |
| 日志 | **slog (标准库)** | Go 1.21+ 内置，结构日志 |
| 配置 | **Viper** | 多环境配置 |
| 迁移 | **golang-migrate** | 纯 SQL 迁移，版本可控 |
| 部署 | **Docker Compose** | 与现有运维体系一致 |

### 1.2 系统分层

```
┌─────────────────────────────────────────────────┐
│                   HTTP Layer                      │
│  gin router → middleware(auth/log/ratelimit)     │
│  → handler(参数校验+绑定) → response              │
├─────────────────────────────────────────────────┤
│                  Service Layer                    │
│  业务逻辑编排、事务管理、权限校验                   │
│  跨模块调用通过 service 接口                      │
├─────────────────────────────────────────────────┤
│                 Repository Layer                  │
│  数据访问(sqlx)、缓存操作(Redis)                   │
│  每张表一个 repository                            │
├─────────────────────────────────────────────────┤
│              Infrastructure Layer                 │
│  MySQL / Redis / 易宝API / BSN          │
└─────────────────────────────────────────────────┘
```

## 3. Redis 缓存策略

| Key 模式 | 用途 | TTL | 说明 |
|----------|------|-----|------|
| `session:{token}` | JWT 黑名单/主动失效 | 与 token 过期一致 | 登出时加入 |
| `sms_code:{phone}` | 短信验证码 | 5min | 防刷 |
| `login_limit:{ip}` | 登录限流计数 | 20min | IP 级别 |
| `product_stock:{id}` | 余量缓存+锁 | — | 下单时 DECR，取消/释放时 INCR；并发用 Lua 保证原子 |
| `order_lock:{order_no}` | 支付幂等 | 30min | 防重复支付回调 |
| `attestation_queue` | 区块链存证队列（Redis List） | — | LPUSH/RPOP 轻量队列 |
| `config_cache` | 系统配置热加载 | 5min | 费率/字典/开关 |

### 余量并发控制（关键）
```
下单时用 Lua 脚本原子操作：
  if redis.call('GET', 'product_stock:'+productId) >= quantity then
    redis.call('DECR', 'product_stock:'+productId, quantity)
    return 1  -- 锁成功
  else
    return 0  -- 余量不足
  end
超时未支付 → INCR 归还余量
```

## 4. 资金安全设计（关键）

> ⚠️ 交易系统最核心的约束。以下每条都是硬规则，代码审查时逐条验证。

### 4.1 金额精度

| 规则 | 说明 |
|------|------|
| 所有金额字段统一 `DECIMAL(12,2)` | MySQL 存储，精确到分 |
| Go 代码中金额用 `int64`（单位：分） | 避免浮点运算误差。展示时 ÷100 |
| 禁止 `FLOAT` / `DOUBLE` | 任何涉及金额的计算都不允许 |
| 金额计算一律用整数运算 | `total = unit_price_fen × quantity × duration_hours` |
| 接口传输金额字段统一为 `string` | JSON 中 `"total_amount": "201600.00"`，防止 JS 数字精度丢失 |

```go
// ✅ 正确：金额用 int64 分
type Order struct {
    UnitPriceFen int64 `json:"unit_price_fen"` // 3500 = ¥35.00
    TotalFen     int64 `json:"total_fen"`
}
// ❌ 错误：金额用 float64
type BadOrder struct {
    Total float64 `json:"total"` // 禁止
}
```

### 4.2 幂等性

| 场景 | 幂等键 | 实现 |
|------|--------|------|
| 下单 | `order_no`（客户端生成 UUID） | 重复 order_no → 返回已有订单，不重复创建 |
| 支付回调 | `yeepay_tx_id` | Redis `SETNX order_lock:{tx_id}` 防重复处理 |
| 分账指令 | `settlement_id` | 数据库唯一约束 `UNIQUE(settlement_id)` |

### 4.3 库存原子性

```
下单锁库存（Redis Lua 原子）：
  EVAL "if redis.call('GET',KEYS[1]) >= ARGV[1] then
          redis.call('DECRBY',KEYS[1],ARGV[1])
          return 1
        else
          return 0
        end" 1 product_stock:{id} {quantity}

超时未支付 → Redis INCRBY 归还 + DB UPDATE stock
取消/退款 → 同上归还
```

### 4.4 三方对账

| 频率 | 内容 | 执行 |
|------|------|------|
| 每日 03:00 | 拉取易宝前一日交易流水 → 逐笔与平台 payments 表勾对 | 定时任务 |
| 差异处理 | 平台有/易宝无 → 查询补单；易宝有/平台无 → 人工核查 | 告警+工单 |
| 对账结果 | 生成对账报表，差异清零后方可结账 | 运营后台可查 |

### 4.5 审计追踪

| 操作 | 记录内容 | 保留 |
|------|----------|:--:|
| 订单创建/支付/退款/冻结 | 操作人、时间、金额、状态变更前后值 | ≥6月 |
| 分账指令发出/完成/失败 | 分账金额、各方应收、实际到账 | ≥6月 |
| 后台资金操作（运营干预） | 操作人IP、操作类型、订单号、金额变化 | ≥6月 |
| 配置变更（费率/分账规则） | 变更前后值、操作人、时间 | ≥6月 |

### 4.6 补偿机制

| 异常场景 | 补偿 |
|----------|------|
| 支付回调丢失 | 定时主动查询易宝支付状态 → 补单 |
| 分账失败 | 重试 ×3 → 人工介入 |
| 超时未支付 | Redis 归还余量 + DB 更新订单状态为 cancelled |

### 4.7 代码级约束

```go
// 所有支付/分账/退款操作必须：
// 1. 在 DB 事务中完成状态变更
// 2. 记录审计日志（同一事务）
// 3. 返回明确错误（不可吞掉 error）
// 4. 关键步骤前后打结构化日志（含 trace_id + order_no）

func (s *PaymentService) HandleCallback(ctx context.Context, req CallbackReq) error {
    tx := s.db.BeginTx(ctx, nil)
    defer tx.Rollback()

    // 幂等检查
    locked, _ := s.redis.SetNX(ctx, "order_lock:"+req.TxID, 1, 30*time.Minute).Result()
    if !locked { return ErrDuplicate }

    // 更新订单状态
    if err := s.orderRepo.UpdateStatusTx(tx, req.OrderNo, StatusPaid); err != nil {
        return fmt.Errorf("update order: %w", err)
    }

    // 审计日志（同一事务）
    if err := s.auditRepo.LogTx(tx, AuditLog{...}); err != nil {
        return fmt.Errorf("audit log: %w", err)
    }

    // 触发分账（异步）
    s.queue.Push(SettlementTask{OrderNo: req.OrderNo})

    return tx.Commit().Error
}
```

## 5. 关键流程

### 5.1 下单→支付→分账时序

```
买家         平台                易宝             机房
 │            │                   │                │
 │ POST /order│                   │                │
 ├───────────►│                   │                │
 │            │ Redis DECR stock  │                │
 │            │ INSERT order      │                │
 │◄───order───┤ (pending_payment) │                │
 │            │                   │                │
 │ POST /pay  │                   │                │
 ├───────────►│                   │                │
 │            │ POST yeepay/pay   │                │
 │            ├──────────────────►│                │
 │            │◄───pay_url────────┤                │
 │◄─pay_url──┤                   │                │
 │            │                   │                │
 │(跳易宝收银台支付)              │                │
 │            │                   │                │
 │            │◄───callback───────┤                │
 │            │ 验签               │                │
 │            │ UPDATE order=paid  │                │
 │            │ POST yeepay/split  │                │
 │            ├──────────────────►│                │
 │            │                    │ 入机房+平台账户 │
 │            │                    │                │
 │            │ 通知机房接单        │                │
 │            ├─────────────────────────────────────►│
 │            │                    │                │ 开通算力
 │            │◄────────────────────────────────────┤ 回填凭证
 │            │                    │                │
 │◄─已开通────┤                    │                │
 │ 确认签收    │                    │                │
 ├───────────►│                    │                │
 │            │ 触发分账完结        │                │
 │            │ ⛓ 存证事件→Redis   │                │
```

### 5.2 区块链存证异步流程

```
业务事件(下单/交付/违规)
      │
      ▼
LPUSH Redis List "attestation_queue"
      │
      ▼ (异步Worker BRPOP消费)
计算 hash → 收集签名 → BSN API 存证
      │
      ├─ 成功 → UPDATE blockchain_attestations SET tx_id, status=confirmed
      └─ 失败 → 重试×3 → 死信告警
```

## 6. API 设计规范

### 6.1 统一响应格式
```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "uuid"
}
```
错误码 0=成功，非 0 见 `pkg/errcode`。

### 6.2 RESTful 命名
```
GET    /api/v1/products              # 列表
GET    /api/v1/products/:id          # 详情
POST   /api/v1/products              # 创建（供给方）
PUT    /api/v1/products/:id          # 更新
PATCH  /api/v1/products/:id/status   # 状态变更

POST   /api/v1/orders                # 下单
GET    /api/v1/orders                # 订单列表
GET    /api/v1/orders/:id            # 订单详情
POST   /api/v1/orders/:id/deliver    # 回填凭证
POST   /api/v1/orders/:id/confirm    # 确认签收
POST   /api/v1/orders/:id/refund     # 申请退款
```

### 6.3 鉴权
- 所有 `/api/v1/*`（除公开）需 `Authorization: Bearer <jwt>`
- 角色权限通过 RBAC 中间件校验
- 运营后台 `/api/v1/admin/*` 需 operator/admin 角色

### 6.4 API 文档组织

详细接口文档按模块分文件存放于 `docs/api/`：
- `auth-api.md` — 注册/登录/认证

- `payment-api.md` — 支付分账
- `intermediary-api.md` — 居间金融
- `admin-api.md` — 运营后台

## 7. 安全设计

| 层面 | 措施 |
|------|------|
| 传输 | HTTPS 全站 |
| 密码 | bcrypt 加密，不可逆 |
| 鉴权 | JWT access(15min)+refresh(7d)，登出加入黑名单 |
| 支付 | 易宝私钥不入库不入前端不进日志，KMS管理 |
| 敏感数据 | 手机/身份证/交付凭证 AES-256 加密存储 |
| 注入防护 | sqlx 参数化查询，输入校验 |
| 限流 | 登录/注册/下单接口 IP+UID 双维度限流 |
| 越权 | RBAC 中间件 + 资源归属校验（买家只看自己的订单） |
| 日志 | 资金/订单/后台操作全留痕，不含敏感明文 |
