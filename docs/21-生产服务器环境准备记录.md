## 4. 安全加固

| 项 | 配置 |
|---|---|
| firewalld | 已启用并开机自启，**仅放行 ssh**（先放行再启用，避免锁死） |
| SSH 暴力破解防护 | 见下方说明 |
| 内核安全参数 | `tcp_syncookies=1`、`rp_filter=1`、禁 `accept_redirects` / `send_redirects` / `accept_source_route` |
| SELinux | Disabled（镜像默认，未改动） |

**fail2ban 的替代方案**：`fail2ban` **不在 Alibaba Cloud Linux 4 源中，EPEL 亦无**。未引入第三方源（生产环境加不受信源本身即风险），改为自研 `/opt/wanxiang/scripts/ssh-autoban.sh` + `ssh-autoban.timer`（每 10 分钟）：1 小时内认证失败 ≥8 次的 IP 写入 firewalld drop 名单。白名单：`/opt/wanxiang/config/ssh_ban_whitelist.txt`。

> ⚠️ **踩坑记录**：曾尝试用 firewalld rich rule `limit value=10/m` 限流 SSH，导致**自己被挡在门外**——该限流会把密钥交换所需的往返包一并计数。已移除，勿重蹈。

## 7. 中间件

配置：`/opt/wanxiang/config/docker-compose.middleware.yml`，凭据：`.env.middleware`（600，openssl 强随机生成）。

| 服务 | 版本 | 关键配置 |
|---|---|---|
| MySQL | 8.0.46 | **仅监听 127.0.0.1:3306**；utf8mb4；`+08:00`；buffer pool 2G；慢查询 >1s；binlog 保留 7 天；内存上限 4G |
| Redis | 7-alpine | **仅监听 127.0.0.1:6379**；强密码；AOF everysec；`maxmemory-policy=noeviction` |

> `noeviction` 是刻意选择：Redis 承载会话与存证队列，用 LRU 淘汰会**静默丢数据**。宁可写入报错也不静默丢失。
