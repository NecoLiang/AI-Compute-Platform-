# 29 · 部署模型申请上架 omnis-api 设计

> 版本：v1.2-draft ｜ 日期：2026-11-10 ｜ 状态：待审查（仅设计，未实现） ｜ 产出：ARCH
> 来源：业务负责人 2026-11-10：「网关就用我们的 omnistoken（万象网关）；现在不适合让用户部署模型后直接上架，而是提出申请后由我们上架，让客户选择自己独立使用还是公开对外使用。」
> 依赖：`docs/27`（一键部署引擎容器、健康检测 L0–L5）、`docs/25`（租约、SSH 管理通道、访问网关）、`docs/05`（Token 工厂 REQ-C-*）。
> 推翻：`docs/24` D-7「只对租约私有可达」、D-8「一键部署与 Token 工厂分离」、Q-43「不提供公网端点」，见 §29.9。

---

## 29.1 目标与边界

| 项 | 口径 |
|---|---|
| 入口 | 买家在一键部署（`docs/27`）的部署处于 `running + healthy` 时**提出上架申请**；平台**人工审核**后由平台上架。买家不能自助上架 |
| 网关 | 统一用 omnis-api（new-api 二开，`token.omnisline.com`，部署在万象机）。不新建模型网关、不给部署单独开公网端点 |
| 两种模式 | **私有（dedicated）**：只有该客户自己的 omnis-api 令牌能调用；**公开（public）**：进入 omnis-api 公开分组，由平台定价，对所有 omnis-api 用户售卖 |
| 不变 | 未上架的部署仍按 `docs/27` §27.4.2 只在租约内 / `ssh -L` 可达；一键部署本身仍免费（Q-35） |
| 不做 | 买家自定义镜像或目录外模型上架；跨租约合并成一个负载均衡池（同一模型多个上架各自一条渠道，由 omnis-api 按渠道权重分流即可）；买家直接改 omnis-api 价格 |

---

## 29.2 总流程

```
买家一键部署 running+healthy（仍私有）
  └─ 买家申请上架：选模式 private/public，填 omnis-api 用户名，勾选上架协议
       └─ 运营审核（模型许可、备案、租期余量、健康记录、公开模式的定价与分成）
            ├─ 驳回 → rejected（写原因）
            └─ 通过 → provisioning
                 ├─ public：执行 §29.5 公开隔离（收回买家 shell 与部署控制、引擎换隔离网络）
                 ├─ 渠道桥登记路由（§29.4）
                 └─ 调 omnis-api 管理接口建渠道（private=专属分组，public=公开分组）→ listed
listed 期间：健康/租约事件 → suspended（禁用渠道）⇄ listed（启用渠道）
下架：买家申请 / 运营下架 / 租约结束 → delisting → 删渠道、撤路由、（public）恢复买家访问 → delisted
```

## 29.3 两种模式

| 维度 | 私有 dedicated | 公开 public |
|---|---|---|
| 谁能调用 | 只有申请人绑定的 omnis-api 账户下的令牌 | 所有可用该公开分组的 omnis-api 用户 |
| omnis-api 落点 | 每个上架一个专属分组 `ded-<listing_no>`，渠道只挂该分组；把分组加入该用户的可用分组 | 渠道挂公开分组（如 `default`），模型名按平台命名规范 |
| 价格 | 建议分组倍率 0（算力已按租期付过费，不再重复收 Token 费），只记用量（Q-49） | 平台定价，走 omnis-api 现有模型价格 / 分组倍率 |
| 买家 shell 与部署控制 | 保留（买家仍可 `ssh -L`、停止、重启） | **上架期间收回**（§29.5） |
| 备案 | 不对公众提供，不触发 REQ-C-003；协议约定买家不得把令牌转给公众使用 | 触发 REQ-C-003 / 050 / 052，未满足不得上架（§29.7） |
| 模型许可 | `commercial_use` 任意（`restricted` 仍需买家确认，同 `docs/27`） | 只允许 `commercial_use=allowed` |
| 包夜租约 | 允许；窗口外渠道禁用 | 不允许（每天停放，无法稳定对外服务） |
| 下架生效 | 立即 | 提前通知期后生效（Q-53），租约到期除外 |

私有模式的价值：买家得到一个标准 OpenAI 兼容 HTTPS 端点 + 令牌 + 用量日志，不必维持 `ssh -L` 隧道；数据面仍只服务买家自己。

## 29.4 数据通路：渠道桥

引擎容器只绑供给方宿主机 `127.0.0.1:<engine_port>`（`docs/27` §27.4.1），omnis-api 在万象机（阿里云北京）。需要一条从北京到供给方宿主机本地端口的受控通路。

**推荐：渠道桥（channel bridge）**——平台自写的小进程，与访问网关同机部署（`cmd/accessgw` 同仓库新子命令或独立部署单元）：

```
omnis-api(万象机) ──HTTP, 北京 VPC 内网──► 渠道桥 :<bridge_port>/<listing_no>/v1/...
                                         │ 校验渠道 key（每个上架一把，只存在 omnis-api 与渠道桥）
                                         │ 去掉 Authorization 头
                                         └─SSH direct-tcpip──► 供给方宿主机 127.0.0.1:<engine_port>
```

| 规则 | 说明 |
|---|---|
| SSH 身份 | **单独一把转发密钥**，与管理密钥分开。管理密钥行带 `no-port-forwarding`（`fleet/keys.go`）保持不变；转发密钥行：`restrict,port-forwarding,permitopen="127.0.0.1:<engine_port>",from="<渠道桥出口 IP>"`，`restrict` 禁止 shell/pty/agent/X11，`permitopen` 只放该部署的引擎端口。上架时经管理通道追加、下架时删除（与安装管理公钥同一套幂等命令模板） |
| 主机指纹 | 复用节点已钉死的指纹（TOFU 结果），不一致即拒绝转发并把上架置 `suspended` |
| 供给方前提 | 宿主机 sshd `AllowTcpForwarding` 不能为 `no`。上架前由渠道桥做一次真实 direct-tcpip 试连（不依赖 root 读 `sshd -T`），失败即审核不通过并写明原因 |
| 渠道 key | 不下发到供给方节点（宿主机上任何进程都能 `docker inspect` 看到引擎参数，`--api-key` 挡不住供给方）。引擎仍不设 API Key，访问控制在渠道桥 |
| 暴露面 | 渠道桥只监听北京 VPC 内网地址，安全组只放万象机内网 IP；不上公网 |
| 连接复用 | 每节点一条 SSH 连接、每请求一个 direct-tcpip 通道；流式响应按块透传，不缓冲；单上架并发上限可配，超限 429 让 omnis-api 换渠道 |
| 日志 | 只记请求时间、上架号、状态码、字节数、耗时；**不记请求体与响应体** |

否决的方案：

| 方案 | 否决原因 |
|---|---|
| 引擎端口直接开到公网（P11 端口段） | 明文 HTTP 过公网；需要在供给方 DOCKER-USER 维护白名单，且 NAT 节点不可用；公网扫描面 |
| 引擎端口开公网 + TLS | 每节点证书签发与轮换、供给方可替换证书，复杂度高于复用已钉死指纹的 SSH |
| 供给方节点反向隧道连平台 | 需要在供给方机器上跑常驻进程，违背 D-4「不装常驻 agent」 |
| omnis-api 直接持有 SSH 密钥 | omnis-api 是 new-api 二开，加 SSH 转发要改上游核心并长期维护分叉；密钥也不应与 Token 业务库同机 |

**万象机与网关主机须在同一阿里云账号、同一北京 VPC**（或经云企业网打通），否则渠道桥只能走公网 + TLS + IP 白名单，本节方案需调整。

## 29.5 公开模式的隔离

当前一键部署里，买家对租约容器有 root，引擎与租约容器在同一租约网络（别名 `omnis-engine`）且挂同一组卡。私有模式下这没有问题（服务的是买家自己）；公开模式下引擎处理的是公众用户的提示词与输出，必须让买家接触不到：

| 风险 | 说明 | 措施 |
|---|---|---|
| 网络窃听 / 篡改 | 租约容器默认带 `NET_RAW`，与引擎同一网桥，可做 ARP 欺骗截获明文 HTTP | 上架前平台用目录镜像 digest **重建**引擎容器，换到独立网络 `omnis-p-<listing_no>-net`（只有引擎），去掉 `omnis-engine` 别名 |
| 抢占同一组 GPU | 租约容器也挂着这些卡，可跑负载压垮公开服务或做侧信道 | **上架期间停止租约容器**（`docker stop`，工作区卷保留），网关拒绝该租约登录（复用撤销机制） |
| 部署控制 | 买家可停止 / 重启部署，影响公开服务可用性 | 上架期间买家部署接口对该部署返回 40900「部署已公开上架，请先申请下架」 |
| 供给方 | 宿主机 root 可访问引擎端口、读容器内存 | 无法技术消除（同 `docs/24` §8），在公开模型页与用户协议中披露，并只对信用分达标的节点开放公开上架（阈值 Q-51） |

结果：公开上架 = 买家把这段租期的整组卡交给平台运营。因此公开模式要求**部署占用该租约的全部卡**，且剩余租期 ≥ 平台下限（Q-52）。下架后平台删除公开引擎、启动租约容器并恢复登录；如需继续私有使用，买家重新一键部署（重新走 `docs/27` checking）。

## 29.6 生命周期联动

平台是渠道状态的唯一驱动方，经 omnis-api 管理接口启用 / 禁用 / 删除渠道（管理凭据只放配置，不入库）；omnis-api 自带的失败自动禁用只作兜底。

| 事件 | 上架状态 | 渠道动作 |
|---|---|---|
| 部署 `degraded/unhealthy`（`docs/27` §27.5） | `listed → suspended` | 禁用 |
| 恢复 `healthy` 并连续通过 N 次 | `suspended → listed` | 启用 |
| 渠道桥转发失败（指纹不符、SSH 断开超阈值） | `suspended` | 禁用 |
| 包夜停放（仅私有） | `suspended` | 禁用；开窗且部署恢复后启用 |
| 租约冻结（挖矿等） | `suspended` | 禁用 |
| 租约到期前 T-10 分钟 / 退款 / 宽限期开始 | `delisting` | 先禁用让在途请求排空，到期删除 |
| 买家申请下架 | `delisting` | 私有立即；公开在通知期结束后 |
| 运营下架 | `delisting` | 立即 |

停机补偿（`docs/25` §25.7.6）只针对租约本身；上架期间渠道停用不额外补偿 Token 用户（omnis-api 会切到同模型其他渠道或报错）。

## 29.7 合规与资金

| 事项 | 口径 / 待确认 |
|---|---|
| 备案（REQ-C-003） | 自部署开源权重向公众提供生成式服务，很可能需要**生成式人工智能服务备案**，而不只是调用已备案模型的登记。omnis-api 渠道 2（自部署 DeepSeek）已在对外服务，同一问题已存在。**公开模式在法务确认依据前不开放**（Q-50） |
| 内容安全（REQ-C-050） | 公开模式必须开启 omnis-api 敏感词拦截与日志留存；未开启不得上架 |
| 备案展示（REQ-C-052） | 公开模型在 omnis-api 模型页标注备案号 |
| 模型许可 | 公开只允许 `commercial_use=allowed`；上架记录保存许可证快照 |
| 收益分配 | 公开模式下公众付给平台的 Token 费，如果再按比例分给买家，平台等于代收代付，有**二清**风险。建议：平台向买家**采购算力 / 用量**（按月结算、买家开票、平台自有账户付款，不走易宝分账），Token 收入是平台自有收入（Q-54，财务 / 法务确认） |
| 账务隔离（REQ-C-021） | Token 收入与用量只在 omnis-api 侧记账；撮合平台只记上架状态与对买家的采购结算，两边不互相扣款 |

## 29.8 数据、接口与任务（草案）

**迁移 038 `model_listings`**：`listing_no`、`deployment_id`、`lease_id`、`order_id`、`buyer_id`、`mode`（private/public）、`state`（applied/rejected/provisioning/listed/suspended/delisting/delisted/failed）、`omnis_username`、`omnis_user_id`、`omnis_group`、`omnis_channel_id`、`public_model_name`、`bridge_port`、`license_snapshot`、`reviewer_id`、`review_note`、`suspend_reason`、`applied_at/listed_at/delist_requested_at/delisted_at`。状态迁移沿用条件 UPDATE + RowsAffected。

**接口**（均 `fleet.enabled=true` 才注册）：

| 角色 | 接口 |
|---|---|
| 买家 | `POST /orders/:id/deployments/:deploy_no/listing`（申请）、`GET …/listing`、`DELETE …/listing`（撤回申请 / 申请下架） |
| 运营 | `GET /admin/model-listings`、`POST /admin/model-listings/:no/approve`（公开模式须填模型名与定价）、`…/reject`、`…/delist` |
| 内部 | 渠道桥 ↔ 主服务：路由表拉取、转发失败上报（复用访问网关的 HMAC + nonce 内部鉴权） |

**任务**：
